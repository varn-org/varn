# 🧭 Roadmap

A per-module gap analysis against what Express, Fastify, FastAPI, Django, and the Node/Python standard libraries give developers **day-to-day**. The bar is real-world apps and keeping Varn **simple to use** — the 20% of features reached for 80% of the time, not exhaustive parity. Open items are tagged **[Essential]** (real apps get painful without it), **[Important]** (commonly needed), **[Nice]** (real but lower frequency), with a rough size.

Keep this file honest. When a gap closes, move it into "Already covered" in the same change.

## Already covered — do not rebuild

- **Web (`http`) server**: Routing with param constraints, optional params and a `*` catch-all wildcard, named routes and reverse URLs, route groups and versioning, global/group/route middleware, shipped middleware (CORS, security headers, CSRF, rate-limit, API-key, JWT + role guards), sessions with rotation, body parsing (json/form/multipart + uploads), full cookie attributes, static files (ETag/range/304/cache + `sendfile`), `ctx:etag()` and `ctx:accepts()` on dynamic responses, gzip response compression negotiated on `Accept-Encoding`, `ctx:sse()` server-sent events, responses streamed through `ctx:write` and `res:write` with chunked encoding or a declared length whose writes resolve once the client took them, WebSockets with broadcast, binary messages, close codes, pings, subprotocols, per-route limits and sends that resolve once the message left, centralized error and 404 handlers, request hardening with a request deadline answered by `504` and an early `413` for a body the head declares too large, listen options checked by name, port `0`, a busy port refused, a server that closes at once or gracefully, multi-process scaling with `SO_REUSEPORT` limited to the worker processes.
- **Web (`http`) client**: One options table in, a `{ status, ok, headers, body, json() }` response out, plus `client.stream` delivering each piece of the body as it arrives with an `onResponse(status, headers)` head callback on every target including the browser, one deadline for the whole request that takes a fraction of a second, connections kept per origin on every transport, downloads resumed through `Range`, and the streaming C++ API `varn::http::client::HttpClient` with cancellation from any thread, progress, a size limit, a body that streams from a callback and typed errors.
- **Data**: The modules `json` (parsed straight into Lua tables and written straight into a Lua buffer, `json.null` with the option `nullValue`, the markers `json.array` and `json.object`, errors that name the key or the line and column) and `xml`, the **`vdo`** component (PDO-style SQL for SQLite/MySQL/Postgres with prepared statements and transactions), the **`redis`** and **`mysql`** components, and the **`pool`** connection pool. The database and cache stories are filled by components, which keeps the C++ core lean.
- **System**: The modules `fs` (read/write/exists/mkdir/remove, streaming `open` handle, `stat`, `readdir`, `rename`, `copy`, `append`, `mkdtemp`), `socket` (TCP/UDP with batched `sendMany` and `recvMany`, TLS client sockets, Unix domain sockets, exclusive binds that report a busy port by its address and share one only through `reusePort`, port 0 with the bound address on listeners and UDP sockets, host names resolved on the I/O pool and `socket.resolve`, connected UDP sockets, broadcast and multicast groups, `TCP_NODELAY`, keepalive, half close, local and peer addresses, a bound on queued sends, pending operations that reject with the close, and errors that name their address and system error), `process` (`exec` with captured stdout/stderr/exit code, `getenv`, `env`, `cwd`, `argv`), `zip` (every entry checked before anything is written, extraction through a folder moved into place, `list` with sizes and an `unsafe` flag), `ffi` (calls through function pointers, casts of light userdata, pointers to const, arrays inside structs, enums, bitfields, `intptr_t`, callbacks that run on the coroutine of the call and raise their error as it was raised with its frames for the failure handler, symbols a host adds, UTF-8 library paths on Windows), `platform`, `datetime`.
- **Crypto**: The functions `digest`, `hmac`, `randomBytes`, constant-time `equals`, `base64`/`base64url`/`hex` codecs, `uuidV4`/`uuidV7`, `hashPassword`/`verifyPassword`, AES-256-GCM `encrypt`/`decrypt`, `rsaEncryptPublic`, `pbkdf2` and `hkdf`.
- **Runtime**: A poll with a time budget for a host that drives the loop once per frame, which repeats passes of jobs, timers and sockets while they make progress, worker pools the host sizes for its device, posts that wake a worker only when one is idle and none is already waking, a browser build that unwinds Lua on the native exceptions of WebAssembly and pumps itself from the event loop of the page, and the module `async` (`sleep`/`yield`/`spawn`/`run`/`promise`/`deferred`, task handles that cancel and close the task, one handler for every failure no caller receives with its traceback and frames, including server handlers, WebSocket and stream callbacks and promises that reject with no one observing them, `promise:catch`, promises that hand every awaiter one shared value instead of a copy each, and the `all`, `allSettled`, `race`, `any`, `timeout` and `mapLimit` combinators, which wait without polling and remove a deadline that was met), leveled `log` with runtime level config, structured key/value fields and a file or rotating sink.
- **Components**: The components `ai`, `scheduler`, `vdo`, `redis`, `mysql`, `pool`, `env`, `validate`, `test`, `retry`.

## Open gaps

### `fs` (native)
- **[Nice]** A `glob` / recursive directory walk. The function `readdir` lists one level, so walking a tree is Lua boilerplate today. *small*

### `http` client (native)
- **[Important]** The desktop transport ignores the proxy of the system and takes no `proxy` option, while the Apple and Android transports follow the proxy of the system. *small*
- **[Nice]** Every transport but the browser holds one thread of `ioPool()` for each request in flight, so no more requests run at once than that pool has threads. *medium*

### `process` (native)
- **[Nice]** A streaming `process.spawn` alongside the buffered `process.exec`, delivering stdout and stderr per chunk instead of one captured result. Long-running children (a build, a log tail) are the case `exec` cannot serve, since it resolves only when the child exits. *medium*
